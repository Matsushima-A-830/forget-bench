# 実験プロトコル

## 実行単位

1回の実行(run)= 1つの設定ファイル × 1バックエンド × N個のシナリオseed × M個の戦略。

`runs/<YYYYMMDD-HHMMSS>-<name>/` に以下を出力する(git管理外)。

| ファイル | 中身 |
|---|---|
| `meta.json` | git commit / 設定ファイル全文 / seed一覧 / モデル名・digest・revision / ライブラリバージョン / GPU / 開始・終了時刻 |
| `requests.jsonl` | 1リクエスト1行: 戦略・シナリオ・質問ID・入力トークン数・出力テキスト・レイテンシ・エラー |
| `scores.jsonl` | 1質問1行: 正解・回答・判定・漏洩判定 |
| `summary.json` | 指標の集計 |
| `progress.jsonl` | 進捗(長時間実行の監視用) |
| `cache/` | `claude` バックエンドのレスポンスキャッシュ |

## 手順

1. `bash scripts/check_env.sh` で環境を確認する。
2. `configs/smoke.yaml`(1シナリオ・数問)で全戦略×対象バックエンドの経路を通す。
3. `dev` 分割で、プロンプトや戦略パラメータを調整する。調整内容は `results/` に書く。
4. 設定を凍結して git commit し、`test` 分割で本実行する。
5. `results/<日付>-<名前>.md` に設定・コマンド・表・気づきを書く。数値は `summary.json` からコピーする。

## 記録ルール

- 途中で落ちた実行も消さない。`results/` に「失敗した実行」として原因と一緒に残す。
- 戦略のバグを直した場合は、直す前の結果を「バグあり」として残し、直した後に再実行する。
- 揺れの扱い: `claude` は同一入力3回、`ollama`/`hf` は seed 固定で1回 + 別seedで2回。表には平均と範囲を載せる。
