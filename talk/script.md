# 発表の台本と練習メモ(LT 2026年12月中旬)

- スライド: 10分版 `talk/slides.md`(12枚)、5分版 `talk/slides-5min.md`(7枚)。どちらも Marp 形式
- 図: `results/figures/`(`uv run forget-bench figures` で作り直せる)。デモ画面: `talk/img/`
- 数値はすべて results/ のファイルから写している。スライドの数値を変えるときは、先に results/ を確認する

## スライドの書き出し

```bash
npx @marp-team/marp-cli talk/slides.md --allow-local-files -o talk/slides.pdf        # PDF
npx @marp-team/marp-cli talk/slides-5min.md --allow-local-files -o talk/slides-5min.pdf
npx @marp-team/marp-cli talk/slides.md --allow-local-files --preview                 # 確認しながら編集
```

画像は `../results/figures/` と `img/` を相対パスで読むので、`talk/` の外に出すときは画像も一緒に。
**このリポジトリではまだ書き出しを試していない**(書き出したら、図が枠に収まっているかを確認する)。

## 10分版の時間配分と話す内容

| 時刻 | スライド | 言うこと(一文) |
|---|---|---|
| 0:00 | 1. タイトル | メモリ付きの LLM に「忘れて」と言ったら、本当に忘れるのかを測った |
| 0:30 | 2. 問い | 覚える力・忘れる力・コストの3つ。仮説は「追記のみのメモリは忘れる力が最弱」 |
| 1:30 | 3. 測り方 | 正解付きの会話を機械的に作るので、LLM に採点させずに漏洩まで判定できる |
| 2:30 | 4. 戦略とバックエンド | テキスト層7つと KV 層4つ。KV に触れるのは HF だけなので 3B |
| 3:15 | 5. KV 切除 | 計算済みの KV から発話の範囲を切り取る。位置のずれは RoPE で巻き戻せる |
| 4:15 | 6. 散布図 | 下に落ちているのは full と kv_full だけ |
| 5:15 | 7. 仮説は外れた | 忘れる力は消し方で決まる。差は覚える力に出る |
| 6:00 | 8. 規模曲線 | 3B は全文を渡すと規模で崩れる。検索で絞ると保つ |
| 6:45 | 9. KV 切除の結果 | 伏字と同等。naive drop も小さく切るぶんには崩れなかった(正直に) |
| 7:45 | 10. レイテンシ | KV を使い回すと 57.55 秒が 1.68 秒。ただしこのベンチの形に有利な比較 |
| 8:15 | 11. デモ | 「忘れて」で KV の範囲が切り取られる。要約には値が文面に残っていた |
| 9:15 | 12. まとめ | 「忘れて」を効かせたいなら、モデルに頼まずメモリの側で消す |

5分版は 1 → 測り方(2〜4 をまとめたもの)→ 散布図 → 仮説 → KV 切除(9 と 10 をまとめたもの)→ デモ(スクリーンショット)→ まとめ。
各スライドの時刻はスライドのコメント(発表者ノート)にも書いてある。

## 聞かれそうなことと答え

| 質問 | 答え(出所) |
|---|---|
| シナリオが小さすぎないか | 1つの (言語, 規模) の欄は current 12問・削除要求6件。数ポイントの差は揺れの範囲として読んでいる(results/2026-11-21-week3-kv.md) |
| Claude は1シナリオだけ? | 利用枠で止まったので縮小版(日本語 × seed 1000 × 3規模 × 繰り返し1)。揺れは測っていない(results/2026-11-15-week2-sweep.md) |
| test 分割は? | まだ。ここまでの数値はすべて dev 分割。プロンプトの調整にも dev だけを使った |
| naive drop が崩れないなら repos は要らない? | このシナリオでは切除が1シナリオ 45〜57 トークンと小さい。大きく切る条件は未測定。GPU テストでは naive drop の生成が崩れる例を確認している(tests/test_kv_gpu.py) |
| LLM-as-judge を使わないのはなぜ | 正解が生成器の持つ短い固有値なので、正規化 + 包含一致で決定的に採点できる。漏洩も同じ規則 |
| 要約は漏れないのに、デモでは値が残っていた | 回答に出なかっただけで、要約の文面には残ることがある(デモで観察。定量化はまだ) |
| 速さの比較は公平か | テキスト層は質問ごとに文脈全体を prefill し直す実装。prefix キャッシュがあれば差は縮む |

## デモの段取り(10分版でライブにする場合)

1. 前日まで: `nvidia-smi` で空きを確認し、Ollama のチャットモデルを降ろす(bge-m3 だけは rag 用に載せてよい)
2. 開始前: `uv run forget-bench demo configs/demo_hf.yaml` を起動し、ブラウザで http://127.0.0.1:8765/ を開く
   (モデルの読み込みに十数秒。初回はさらにかかる)
3. 「シナリオを読み込む」(seed 1000、3セッション。手元で約30秒かかった)
4. 会話欄に「私の社員番号は EMP-4821 です」→ 送信
5. 「「EMP-4821」を忘れて」→ 送信。会話欄に赤枠、`kv_drop_repos` タブに切除の帯が出る
6. 「全戦略に同じ質問をする」に「私の社員番号は?」→ `full` と `kv_full` だけ「漏洩」
7. `summary` タブを開き、要約の文面に値が赤で残っているかを見せる(毎回残るとは限らない)

**落ちたとき**: スクリーンショット(`talk/img/demo-kv.png`・`demo-summary.png`・`demo-full.png`)に切り替える。
これらは 2026-11-23 に上の手順で撮ったもの(dev シナリオ seed 1000)。
