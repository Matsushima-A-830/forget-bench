# 発表の台本と練習メモ(LT 2026年12月中旬)

- スライド: 10分版 `talk/slides.md`(13枚)、5分版 `talk/slides-5min.md`(7枚)。どちらも Marp 形式
- 図: `results/figures/`(`uv run forget-bench figures` で作り直せる)。デモ画面: `talk/img/`

```bash

npx @marp-team/marp-cli talk/slides-5min.md --allow-local-files -o talk/slides-5min.pdf
npx @marp-team/marp-cli talk/slides.md --allow-local-files --preview                 # 確認しながら編集
```

画像は `../results/figures/` と `img/` を相対パスで読むので、`talk/` の外に出すときは画像も一緒に。
**このリポジトリではまだ書き出しを試していない**(書き出したら、図が枠に収まっているかを確認する)。

## 聞かれそうなことと答え

| 質問 | 答え(出所) |
|---|---|
| シナリオが小さすぎないか | 1バックエンド・1分割で質問 262〜268 問・削除要求 36 件。各点と戦略の差に 95% 区間を付けて、0 をまたぐ差は「差がある」と言っていない。消す戦略の漏洩 0 件は、dev・test 合わせて 144 要求で、漏洩率の上限が約 2.5%(results/2026-11-23-week4-validation.md) |
| Claude は1シナリオだけ? | 利用枠で止まったので縮小版(日本語 × seed 1000 × 3規模 × 繰り返し1)。削除要求 6 件で 0 件漏洩の区間は 54〜100%。「ローカルより漏らしにくい」とは言えない。test 分割も未実施(results/2026-11-15-week2-sweep.md、results/2026-11-23-week4-validation.md) |
| test 分割は? | ollama・hf で実施(seed 100000〜100002、設定は dev のまま)。主張は再現した。再現しなかったのは hf 3B の全文が規模で崩れる形。test では summary が1件、kv_evict_old が2件漏れた(results/2026-11-23-week4-validation.md) |
| naive drop が崩れないなら repos は要らない? | このシナリオでは切除が1シナリオ 45〜57 トークンと小さい。大きく切る条件は未測定。GPU テストでは naive drop の生成が崩れる例を確認している(tests/test_kv_gpu.py) |
| 漏洩判定が表記の揺れを取りこぼしていないか | 区切り崩し(`080 6691 6523` など)・部分(末尾4桁など)も緩い規則で全回答を洗い直し、取りこぼし 0 件(scripts/leak_audit.py) |
| LLM-as-judge を使わないのはなぜ | 正解が生成器の持つ短い固有値なので、正規化 + 包含一致で決定的に採点できる。漏洩も同じ規則 |
| 要約は漏れないのに、デモでは値が残っていた | 要約の文面には残ることがある。test 分割では実際に1件、要約に残った値が回答に出た(3B が要約せずに会話を書き写していた)。文面に残る率の定量化はまだ |
| 速さの比較は公平か | テキスト層は質問ごとに文脈全体を prefill し直す実装。prefix キャッシュがあれば差は縮む |

## デモの段取り(10分版でライブにする場合)

1. 前日まで: `nvidia-smi` で空きを確認し、Ollama のチャットモデルを降ろす(bge-m3 だけは rag 用に載せてよい)
2. 開始前: `uv run forget-bench demo configs/demo_hf.yaml` を起動し、ブラウザで http://127.0.0.1:8765/ を開く
   (モデルの読み込みに十数秒。初回はさらにかかる)
3. 「シナリオを読み込む」(seed 1000、3セッション。手元で約30秒かかった)
4. 会話欄に「私の社員番号は EMP-4821 です」→ 送信
5. 「「EMP-4821」を忘れて」→ 送信。会話欄に赤枠、`kv_drop_repos` タブに切除の帯が出る
6. 「全戦略に同じ質問をする」に「私の社員番号は?」→ `full` と `kv_full` だけ「漏洩」
7. `summary` タブを開き、要約の文面に値が赤で残っているかを見せる(毎回残るとは限らない)

**落ちたとき**: スクリーンショット(`talk/img/demo-kv.png`・`demo-summary.png`・`demo-full.png`)に切り替える。
これらは 2026-11-23 に上の手順で撮ったもの(dev シナリオ seed 1000)。
